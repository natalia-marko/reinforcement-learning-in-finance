Neural Architecture (Actor-Critic)
Actor Network (Makes Allocation Decisions):
├── Feature Extraction: 512 → 256 neurons
├── Multi-Head Attention: 8 heads (captures asset correlations)
├── LSTM: 2 layers, 128 hidden (temporal patterns)
└── Softmax Output: Valid portfolio weights

Critic Network (Evaluates State Value):
└── Deep MLP: State → 512 → 256 → 128 → 1 (value)

PPO Training Algorithm

Exploration: Starts at 40%, decays to 5% minimum
Clipped objective: Prevents catastrophic policy updates
Entropy bonus: 0.05 coefficient encourages diversity
Early stopping: Patience=50 episodes on validation Sharpe

⏺ PPO Model Architecture Explained

  What We're Using

  model = PPO(
      "MlpPolicy",           # Actor-Critic MLP
      train_env,
      policy_kwargs={
          'net_arch': [256, 256],  # Shared layers
          'activation_fn': nn.Tanh
      },
      ...
  )

  Actor-Critic Architecture

  PPO uses two networks (but we share layers):

                      Input: State (338 dims)
                             ↓
                      ┌─────────────┐
                      │ Shared MLP  │
                      │  256 → 256  │
                      └─────────────┘
                             ↓
                ┌────────────┴────────────┐
                ↓                         ↓
         ┌─────────────┐          ┌─────────────┐
         │   ACTOR     │          │   CRITIC    │
         │  (Policy)   │          │   (Value)   │
         └─────────────┘          └─────────────┘
                ↓                         ↓
        Action: 7 weights          Value: scalar
        (portfolio allocation)     (expected return)

  Actor (Policy Network)

  Output: Continuous action distribution for 7 asset weights

  # For each asset, outputs:
  # - Mean (μ) of Gaussian distribution
  # - Log std (σ) of Gaussian distribution

  # Action sampling:
  action = μ + σ * noise  # Then softmax to get weights that sum to 1

  The policy learns: "Given this market state, what portfolio weights maximize future rewards?"

  Critic (Value Network)

  Output: Single scalar V(s) = expected cumulative reward from state s

  Used for:
  - Computing advantage estimates (GAE)
  - Reducing variance in policy gradient

  The critic learns: "How good is this market state for making money?"

  How PPO Training Works

  1. Collect rollouts: Run policy, collect (state, action, reward) tuples
  2. Compute advantages: A(s,a) = Q(s,a) - V(s)
  3. Update policy: Maximize reward while staying close to old policy (clipping)
  4. Update value function: Minimize MSE between V(s) and actual returns

  Action Space for Portfolio

  # Action space: Box(low=-1, high=1, shape=(7,))
  # Raw output from network: [-0.3, 0.8, 0.1, -0.5, 0.2, 0.4, 0.6]

  # Converted to weights via softmax:
  # weights = softmax(raw_action) = [0.09, 0.27, 0.13, 0.07, 0.15, 0.18, 0.11]
  # Sum = 1.0 ✓

  Key PPO Hyperparameters

  | Parameter  | Value | Purpose                         |
  |------------|-------|---------------------------------|
  | clip_range | 0.2   | Limits policy change per update |
  | ent_coef   | 0.01  | Encourages exploration          |
  | vf_coef    | 0.5   | Value loss weight               |
  | n_epochs   | 10    | Updates per batch               |
  | gae_lambda | 0.95  | Advantage estimation smoothing  |

  Why PPO for Portfolio?

  Pros:
  - Stable training (clipping prevents catastrophic updates)
  - Works with continuous actions (portfolio weights)
  - Sample efficient for on-policy methods

  Cons:
  - On-policy = can't reuse old data
  - Needs many environment interactions
  - Can still overfit with small datasets (our problem)

  ---
  Alternative approaches used in industry:
  - SAC (Soft Actor-Critic): Off-policy, better sample efficiency
  - TD3: Off-policy, handles continuous actions well
  - Model-based RL: Learn market dynamics, plan ahead

  2. LSTM + PPO (Excellent Idea!)

  Current MLP is memoryless - it sees each state independently. But markets have:
  - Regime persistence (bull/bear markets last months)
  - Momentum/mean-reversion patterns
  - Autocorrelation in volatility

  LSTM-PPO Architecture

                  Time Series Input
                        ↓
      ┌─────────────────────────────────┐
      │   State t-3  →  LSTM (128)      │
      │   State t-2  →  LSTM (128)      │
      │   State t-1  →  LSTM (128)      │
      │   State t    →  LSTM (128)  ────┼──→ Hidden State
      └─────────────────────────────────┘
                        ↓
                ┌─────────────┐
                │  MLP 256    │
                └─────────────┘
                        ↓
                Actor / Critic

  Implementation with sb3-contrib

  from sb3_contrib import RecurrentPPO

  model = RecurrentPPO(
      "MlpLstmPolicy",
      train_env,
      policy_kwargs={
          'lstm_hidden_size': 128,
          'n_lstm_layers': 1,
          'shared_lstm': True,
          'net_arch': [256],  # After LSTM
          'activation_fn': nn.Tanh
      },
      learning_rate=3e-4,
      n_steps=2048,
      batch_size=64,
      n_epochs=10,
      gamma=0.99,
      ent_coef=0.01,
      verbose=1
  )

  Why LSTM-PPO Could Work Better

  | Aspect           | MLP                 | LSTM                    |
  |------------------|---------------------|-------------------------|
  | Memory           | None                | Sequences of states     |
  | Regime detection | Must be in features | Can learn from patterns |
  | Momentum         | Explicit features   | Implicit + explicit     |
  | State size       | 338                 | 338 per step × sequence |
